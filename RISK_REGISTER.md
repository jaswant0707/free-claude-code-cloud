# Risk Register: Free Claude Code Cloud

**Date:** November 2026  
**Security & Reliability Lead:** DevSecOps & Cloud Architect  

---

| Risk ID | Risk Description | Severity | Likelihood | Impact | Mitigation Strategy | Monitoring & Safeguards |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **RSK-001** | **Vercel Execution Timeout (60s Hobby limit):** Ultra-deep reasoning models (e.g. Claude 3.7 Sonnet or DeepSeek R1) with very long generation times may exceed Vercel Hobby's 60s execution cap. | Medium | Medium | HTTP 504 Gateway Timeout on very large requests | 1. Streaming flushes initial chunks immediately (TTFT < 1s).<br>2. Document Vercel Pro (300s duration) upgrade path.<br>3. Provide self-hosted Docker alternative for unlimited duration. | Track request lifetimes in `RequestOutcomeMiddleware`. |
| **RSK-002** | **Ephemeral `/tmp` Storage Reset:** Configuration changes made in the web Admin UI to `/tmp/.fcc` reset when serverless instances recycle. | Low | High | Temporary settings reset on cold start | 1. Document that production provider keys must be configured in Vercel Project Environment Variables.<br>2. Environment variables always take precedence and persist indefinitely across all serverless cold starts. | Verified precedence in `compose_settings_snapshot`. |
| **RSK-003** | **Credential Exposure in Git or Public Logs:** Leaking `OWNER_PASSWORD`, `MASTER_API_TOKEN`, or provider API keys in GitHub or console logs. | Critical | Low | Complete account or quota compromise | 1. Hardened `.gitignore` excluding all `.env*`, `.vercel`, `*.db`, certificates.<br>2. Mask secrets in Admin UI (`********`).<br>3. Loguru sanitizes authorization headers.<br>4. Secrets configured exclusively in Vercel encrypted dashboard. | Automated pre-commit scans with zero secrets tracked. |
| **RSK-004** | **Open Proxy / Quota Drainage:** Unauthorized internet crawlers discovering the public URL and making LLM calls using the owner's keys. | Critical | Low | Provider quota exhaustion and bill shock | 1. Cloud deployment automatically forces `PROXY_AUTH_ENABLED=true`.<br>2. All `/v1/...` requests without valid `MASTER_API_TOKEN` are rejected with 401 Unauthorized.<br>3. Fail closed if token is not configured. | Tested in `test_cloud_proxy_unauthenticated_requests_rejected`. |
| **RSK-005** | **Brute-Force Password Guessing on `/login`:** Automated credential stuffing attacks against the single-owner login endpoint. | High | Medium | Unauthorized admin access | 1. Progressive delay on repeated login attempts.<br>2. Constant-time password comparison (`secrets.compare_digest`).<br>3. Generic error messages ("Invalid email or password").<br>4. Audit logging of failed IP attempts without logging passwords. | Verified in `test_auth_rate_limiting`. |
| **RSK-006** | **Persistent Background Bots Incompatibility:** Discord and Telegram long-polling bots cannot run as continuous daemons in serverless functions. | Low | High | Telegram/Discord bot offline in serverless mode | 1. Clearly document that serverless is optimized for request-driven API proxying and Admin UI.<br>2. Provide complete production Docker container files for users wanting 24/7 background bots on a VPS. | Explicitly classified in `FEATURE_COMPATIBILITY_MATRIX.md`. |
| **RSK-007** | **Upstream Provider Rate Limits & Outages:** Single AI provider going down or throttling requests. | Medium | Medium | Request failure for coding agents | 1. Original FCC multi-key rotation automatically switches to secondary keys.<br>2. Dynamic provider fallback chains route requests to alternative providers (e.g. from NVIDIA NIM to OpenRouter or Groq). | Handled by `ProviderRuntimeManager` fallback engine. |
